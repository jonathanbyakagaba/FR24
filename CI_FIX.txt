Second instalment: the notifier, and months that close themselves

1) Open  https://github.com/jonathanbyakagaba/FR24/upload/main
   drop in  CI_FIX.txt  and  ci_fix.tar.gz
   sha256 f32b21033fd5bfc5d6bf62ea32de5f55a1c8beaf801109854108511df42f475f   (9,152 bytes)
   Commit directly to the main branch -> Commit changes.

2) In the codespace terminal:

cd /workspaces/FR24
git pull
tar xzf ci_fix.tar.gz || tar xzf ci_install.tar.gz
rm -f ci_fix.tar.gz ci_install.tar.gz
git add -A
git status --short
git commit -m "CI: notify job posts to FR24-status issue; months close themselves via tools/month_to_close.py"
git push

3) One-time, in the browser: after the first run that posts, open the issue titled FR24-status and
   click "Subscribe" (right sidebar). Every entry after that reaches you by email. If the issue does
   not exist yet, that is normal: the notifier creates it the first time there is something to say.

What is in this bundle
  .github/workflows/fr24-nightly.yml   fetch exit code captured properly (the old `rc=$?` after the
                          command was never reached, because bash -e stops there); a "what the capture
                          reported" step; commit/push reports pushed=true/false and the file count; the
                          freeze step now asks the branch which month is finished-but-open; new `notify`
                          job posting one comment per event that matters, continue-on-error so a broken
                          notifier can never look like a failed build.
  tools/capture_summary.py    capture_manifest.json -> step outputs (zeros + "no fetch this run" when
                          there is no manifest). It is a file because a here-doc cannot sit at column
                          zero inside a `run: |` block.
  tools/month_to_close.py     oldest month folder that is past, and has no .closed marker, and is not
                          the archive's live month. Tested: silent while October is still the live
                          month, prints 2026-10 when the archive is treated as November.
  tools/CI.md                 both of the above written down.

Verified here: the YAML parses, all 8 run blocks pass `bash -n`, both new scripts compile and the
month logic was exercised on the real folders. NOT verified: the `gh api` calls in the notify job,
which need a runner token I do not have here. If they fail, the step is continue-on-error: the data
still lands and the run stays green, you just get no comment - which is the trade I chose.
